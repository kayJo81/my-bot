# 워치리스트 뉴스 자동 블로그 절차

사용자 요청(2026-11-21): 워치리스트 종목 + 앤트로픽·오픈AI에 관한 미니 블벅터 속보나 검색되는 뉴스·분석이 나오면
알아서 블로그 글을 쓰고, 쉽게 이해되는 인포그래픽을 함께 넣어 네이버 블로그에 올린다.

## 대상
- `auto_blog/watchlist.json`: CNBC 워치리스트(9개 그룹) + AI Lab(앤트로픽 ANT, 오픈AI). ETF(SOXX·IGV·CLOU·ITA·UFO)는 제외.

## 한 번 실행할 때
1. `cd my-bot && git pull` 후 `python3 scripts/watch_news.py` → 지난 실행(`auto_blog/state.json`의 last_ts) 이후 관련 속보 목록.
   - 사이트 접속이 막히면 이 단계는 건너뛰고 2번 검색만 한다.
2. 후보 고르기 (한 번에 최대 2편)
   - 글감이 되는 것: 실적·가이던스, 인수합병·투자, 대형 계약·수주, 규제·소송·조사, 경영진 변화, 신제품·로드맵 발표,
     의미 있는 증권사 분석(목표가 대폭 변경, 신규 커버), 공시. ★중요(imp) 속보와 여러 매체가 다룬 소식을 우선.
   - 글감이 아닌 것: 단순 주가 등락 속보, 지수·업종 시황, 이름만 스친 기사, 루머 한 줄, 시장 무관 기업 뉴스(장애 공지 등).
   - 이미 쓴 주제는 건너뛴다: `auto_blog/state.json`의 posted 목록과 `blog/` 폴더 이름·제목을 확인.
     같은 주제라도 새 사실(공식 발표, 숫자 확정)이 나오면 '업데이트'로 쓸 수 있다.
   - 쓸 만한 게 없으면 글을 쓰지 않는다. 억지로 채우지 않는다.
3. 사실 확인: WebSearch로 원 출처(로이터·블룸버그·CNBC·WSJ·FT·기업 IR·SEC 공시)를 찾아 확인한다.
   직접 막힌 사이트는 `fetch-text.yml`(Actions)로 읽는다. 확인 못 한 숫자·인용은 쓰지 않고, 보도 단계면 '보도'라고 쓴다.
4. 인포그래픽: `scripts/blog_cards.js`의 `const pages=[...]`를 바꿔 4~6장(pre-1.jpg …).
   실행 `NODE_PATH=$(npm root -g) node <파일> <출력폴더>`, 1242px로 맞춰 저장. 쉬운 말, 핵심 숫자 크게, 출처 한 줄.
   만든 뒤 몇 장 열어 글자 겹침·잘림을 확인한다.
5. 본문 `blog/<YYYY-MM-DD>-<주제>/body.txt`: `BLOG_STYLE.md`를 따른다(첫 줄 제목, 1~3문장 문단, [그림N] 자리,
   "여기가 중요한 부분인데...", 투자 관점 한두 문단, 마지막 "가장 먼저 볼 것은 …" 한 줄, 출처·투자권유 아님 한 줄).
6. 커밋·푸시 후 `post-blog.yml` 실행: dir, publish "1", category는
   테슬라·스페이스X(xAI 포함) → "테슬라와 스페이스X", 그 밖 → "금융과 투자 넋두리".
   실행 로그의 "발행을 눌렀습니다" 주소를 확인하고, 주소에 글 번호가 없으면 RSS(fetch-text로 rss.blog.naver.com/yidiar.xml)에서 찾는다.
7. `auto_blog/state.json` 갱신: last_ts = watch_news.py의 until, posted에 {date, ticker, topic, url} 추가 → 커밋·푸시.
8. 한국어로 짧게 보고: 올린 글 제목·주소, 검토했지만 건너뛴 주요 소식 한두 개와 이유. 올린 글이 없으면 그렇다고만.

## 지킬 것
- 지어내지 않는다. 미래에셋 김영건 애널리스트 견해는 인용하지 않는다.
- 사람 얼굴·개인정보가 담긴 이미지는 쓰지 않는다.
- 하루 최대 20편(한국 날짜 기준, state.json의 posted에서 오늘 날짜 개수로 확인). 같은 종목은 하루 1편(큰 후속 소식만 예외).
